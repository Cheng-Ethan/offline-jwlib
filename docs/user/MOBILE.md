# 在手机上使用 / Mobile guide

[English](../en/user/MOBILE.md) · [安装到设备](INSTALL.md) · [使用指南](USAGE.md)

手机上运行的不是“网页版”，而是**一个本地 HTML 文件**。浏览器/容器 App 必须允许它读写本地存储，否则书和笔记无法保存。下面按平台给出具体做法；所有步骤都建议先用一份测试 JWPUB 验证，再导入真实资料。

## 1. iPhone / iPad

### 推荐：Sitecase

Sitecase 支持把本地 HTML 作为项目导入，是目前最接近目标环境的方案。

1. 在旧项目里导出完整备份：`更多 → 备份图书馆`。
2. 把 `offline_library.html` 复制到手机（文件 App / AirDrop / 网盘均可）。
3. 在 Sitecase 中新建项目并导入该 HTML。
4. 打开新项目，使用 `更多 → 恢复备份` 导入刚才的备份。
5. 验证：目录、正文、图片、笔记、书签、历史是否正常。
6. 确认无误后再删除旧项目。

注意：

- 不同 HTML 项目可能使用隔离的本地数据空间，新项目不会自动看到旧书；
- Sitecase 的系统文件选择器、持久化批准策略需要在你的真机上确认；
- 不要只复制 HTML 而不恢复备份，否则新项目里是空的。

### 备选

其他能导入本地 HTML 且允许 WebView 本地存储的容器 App 也可以，但必须先做“导入 → 阅读 → 备份 → 恢复”四步验证。纯 Safari 直接打开 `file://` 通常不适合长期保存数据。

## 2. 安卓手机 / 平板

### 方案 A（推荐）：本地 HTTP 服务

用一个本地 shell/服务器 App 给 HTML 一个稳定地址，避免 `file://` 的存储限制。

以 Termux 为例：

1. 安装 Termux，并安装 Python：

   ```sh
   pkg update
   pkg install python
   ```

2. 把 `offline_library.html` 放到手机存储，例如 `/sdcard/Download/`。
3. 在 Termux 中启动服务：

   ```sh
   cd /sdcard/Download
   python3 -m http.server 8080 --bind 127.0.0.1
   ```

4. 在 Chrome / Edge 中打开：

   ```text
   http://127.0.0.1:8080/offline_library.html
   ```

5. 验证导入、图片、备份与恢复都正常后，可以把这个地址添加到主屏幕。

优点：浏览器把 HTML 当作正常站点，本地数据与文件链接行为更接近桌面 Chrome。  
注意：服务只监听本机 `127.0.0.1`，不对外网开放；不同手机/浏览器组合仍需真机验证。

### 方案 B：WebView / HTML Viewer 容器

选择能打开本地 HTML **并允许本地存储**的 App：

1. 把 HTML 放进手机存储；
2. 用该 App 打开，按提示授予文件/存储权限；
3. 立刻做一次“导入样本 → 关闭 App → 重新打开 → 书还在吗”的测试；
4. 再做完整备份/恢复验证；
5. 只有在数据能持久保存后才导入真实资料。

这类 App 差异很大：有的会把每个文件当独立 origin，有的会清缓存，有的不支持大文件。不要只看“能打开”，要看“关掉再开数据还在”。

### 不推荐：直接 `file://` 打开

部分安卓浏览器会限制 `file://` 下的本地数据，或把每个文件视为独立来源，导致书“下次打开就没了”。如果一定要试，请先备份，并接受数据可能丢失的风险。

## 3. 移动端使用建议

- 优先导入较小 JWPUB；大文件先在桌面 Chrome 导入，再备份/恢复到手机。
- 每次升级前导出完整备份，并保留旧 App 项目。
- 图片和复杂排版在手机上最依赖真机验证；发现异常请记录设备、App 版本与出版物样本。
- 应用不会联网；外链点击会被拦截，这是预期行为。

遇到打不开或数据丢失，请先按 [FAQ](FAQ.md) 排查，再看 [TESTING 移动端矩阵](../dev/TESTING.md)。
